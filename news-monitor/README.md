# 联播夜读 · 每日新闻联播联动简报

一个在本地运行的每日新闻监控程序：自动抓取央视网《新闻联播》当日节目单、分条视频与文字稿，结合 B 站 UP 主 **你好小谢同志**、**原点公社** 的公开视频信息，生成一份「文字 + 原片视听」的晚间简报。

**新版不再使用 TTS**：右侧播放器直接播放央视《新闻联播》原片和原声；B 站 UP 联动使用 B 站原视频内嵌播放器，包含原视频画面与原声。

## 一、快速启动

### Windows 一键启动

双击桌面上的 **「联播夜读」** 快捷方式，或项目目录内的 **`启动.bat`**。

- 桌面快捷方式会先检查服务状态：未运行时会隐藏启动后台服务，再打开浏览器；
- 已运行则直接打开；
- 本地地址：**<http://127.0.0.1:8766>**。

当前环境已配置登录自启：Windows 登录后服务会在后台隐藏启动，并自动抓取最新一期。

### 命令行启动

```powershell
cd news-monitor
python app.py
```

然后访问 <http://127.0.0.1:8766>。

> 项目内置 `vendor/` 依赖（Flask、requests、BeautifulSoup、jieba 等），一般无需额外安装。新机器可执行 `pip install -r requirements.txt`，需要 Python 3.10+。

## 二、新版界面

![桌面原片播放](docs/desktop-original.png)

- **今日重点**：自动选出三条主线，点击「看原片」直接播放对应央视片段。
- **今日解读**：央视、你好小谢同志、原点公社三方联动文本。
- **UP 素材 · 原视频原声**：每个 UP 的原视频入口 + 按话题顺序估算的原声起点。
- **全部条目**：每条新闻有独立原片按钮、原稿展开、央视页面链接。
- **右侧「原片视听」**：CCTV HLS 原片视频 + 原声，支持进度拖动、连续播放、上一条/下一条、静音；原片清单切换 13–16 条新闻。
- **跳转修正**：视频 seek 过程中忽略旧时间更新，等 seek 完成后再高亮，避免回跳第一句；语音对齐后的字幕改为非重叠边界，杜绝同一时刻选中不同句导致突然跳句。
- **2.2.4 后台播放（安卓）**：原片进入后台/锁屏后音频不中断，通知栏显示当前字幕，可暂停/继续/停止；返回 App 自动续播。通知需系统允许。安卓安装包见 `android-build/output/联播夜读-2.2.4.apk`
- **2.2.3 Qwen 强制对齐**：桌面后端内置 Qwen3-ForcedAligner-0.6B 服务（`qwen_align.py` + `/api/forced-align/upload`），电脑端自动使用；安卓在同步弹窗填后端地址，上传原片+文字稿后按词级时间戳重建字幕。
- **2.2.2 绝对时间轴**：字幕位置只由 `video.currentTime` 二分查表决定，不再用检测器/相对计时；Vosk 词时间戳 + 文字稿单调锚定，采访和资料片不会推偏文字稿；seek 后天然重同步。
- **2.1.1 自动词锚定**：Vosk 识别词按置信度与文字稿做单调锚定，采访/资料片等文字稿外语音不会带着字幕乱跑；点句校准保留用于少量残余偏差。
- **2.0.0 新增「点句校准」**：播放/暂停时点右侧「点句校准」，再点文字稿中音频正在读的句子，程序记录时间锚点并插值修正全片字幕/高亮；重复点击加权学习，自动保存，可清除本段校准。
- **1.1.9 修复**：关闭后台分析音轨，消除重声；原生/网页统一使用非重叠词级时间轴；升级重置旧同步偏移。
- **Qwen 强制对齐服务**：首次启动后模型懒加载（`news-monitor/models/Qwen3-ForcedAligner-0.6B`），GPU 可用时使用 CUDA，否则 CPU；服务接口见 `qwen_align.py` 和 `/api/forced-align/upload`。
- **离线语音识别对齐 + 微调**：内置 Vosk 中文小模型，对原片音频做词级时间对齐；首次播放某条会提示“语音校准中”，校准完成后跳转/暂停/继续都以真实语音位置为准，不再靠停顿比例猜。电脑和安卓一致，并提供「字幕同步」控件（−2.0s～+2.0s，每步 0.2s，自动保存）。
- **清晰度**：优先使用 CCTV 1200 档 HLS（1280×720），hls.js 自动选最高码率，全屏放大更清晰。
- **B 站原视频弹层**：小谢/原点的原视频在页内播放，包含原声，可全屏；文字和引语链接到对应 B 站视频。

### B 站「切片」说明

B 站没有向普通用户开放这些视频的字幕/章节时间码，无法精确知道某段观点出现在第几秒。因此：

- 视频和文本链接都是**真实的 B 站原视频**；
- 「原声片段」的起点按视频标题/简介中的话题顺序估算，并在界面上标注「按话题顺序估算」；
- 打开 B 站播放器后可拖动进度条精确定位。

## 三、原片与数据

- 新闻事实与文字稿：央视网 `tv.cctv.com`；
- 完整版节目信息：`vdn.apps.cntv.cn` 播放接口，包含每条新闻的起止时间码与独立 mp4；
- 原片播放：桌面优先使用 HLS + hls.js（CCTV HLS 支持跨域），失败时回退 mp4；
- UP 主内容：B 站公开搜索接口（WBI 签名），保留标题、简介、标签原话；
- 摘要：规则算法从央视原稿抽取，不依赖外部大模型；
- **不生成任何 TTS 音频**，也不调用 edge-tts。

## 四、手机 / 平板访问电脑版

服务监听 `0.0.0.0`，同一 Wi-Fi 下可访问：

1. 电脑打开 <http://127.0.0.1:8766/mobile> 显示二维码；
2. 手机/平板扫码进入；
3. Android Chrome 可添加到主屏幕。

如果手机打不开，运行项目目录的 **`开放手机访问.bat`** 允许 TCP 8766 入站。

## 五、跨网络远程访问

需要手机在 4G/5G/其他网络看电脑版时：

1. 双击 **`启动远程访问.bat`**；
2. 自动打开 <http://127.0.0.1:8766/remote> 显示公网二维码；
3. 手机扫码访问，首次若出现安全提示点 Continue to Site；
4. 关闭隧道：**`关闭远程访问.bat`**。

免费隧道地址是临时的，电脑重启/断网后重新运行脚本即可；长期固定地址建议使用带账号的 Cloudflare Named Tunnel、ngrok 或 Tailscale。

## 八、配置

编辑 `config.json`：

| 字段 | 说明 |
| --- | --- |
| `port` | 服务端口，默认 `8766` |
| `host` | 监听地址，默认 `0.0.0.0`；仅本机可改回 `127.0.0.1` |
| `monitor_time` | 每日自动抓取时间，默认 `19:35` |
| `bilibili.cache_ttl_hours` | B站视频缓存时长 |
| `bilibili.ups[].name / uid` | 联动的 UP 昵称与 UID |

> `default_voice` / `voices` 字段已随 TTS 取消，不再使用。

## 十、常见问题

| 现象 | 处理 |
| --- | --- |
| 原片黑屏/无法播放 | 检查 CCTV HLS/mp4 网络；点「央视原片」打开原网页；桌面端已带 hls.js 回退 |
| B 站原视频不显示 | 检查 B 站 iframe 网络；点「B站打开」在浏览器观看 |
| B 站时间点不准 | 按话题顺序估算，打开播放器后手动拖动；没有公开字幕/章节时无法精确 |
| 手机扫码打不开 | 运行 `开放手机访问.bat`，确认同一 Wi-Fi |
| 远程链接失效 | 免费隧道地址会变化，重新运行 `启动远程访问.bat` 并重新扫码 |
| 快捷方式无效 | 运行 `create-desktop-shortcut.ps1` 重建 |
